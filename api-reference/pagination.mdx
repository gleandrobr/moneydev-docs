All MoneyDev list endpoints use **cursor-based pagination**. Rather than relying on numeric page offsets (which can produce inconsistent results as data changes), the API uses opaque cursors derived from resource IDs. This guarantees stable, consistent pages even when new records are created or deleted between requests.

## Query Parameters

<ParamField query="limit" type="integer" default="20">
  Number of records to return per page. Accepts a value between `1` and `100`.
</ParamField>

<ParamField query="after" type="string">
  Cursor for forward pagination. Pass the ID of the **last item** from the previous page to retrieve the next page of results.
</ParamField>

<ParamField query="before" type="string">
  Cursor for backward pagination. Pass the ID of the **first item** from the current page to retrieve the previous page of results.
</ParamField>

## Response Envelope

Every list response wraps results in a standard envelope:

```json
{
  "data": [...],
  "meta": {
    "has_more": true,
    "total": 1500,
    "cursor": {
      "after": "pay_abc123",
      "before": "pay_xyz789"
    }
  }
}
```

<ResponseField name="data" type="array" required>
  The array of resource objects for the current page.
</ResponseField>

<ResponseField name="meta.has_more" type="boolean" required>
  `true` if additional pages exist after the current page; `false` if this is the last page.
</ResponseField>

<ResponseField name="meta.total" type="integer" required>
  Total number of records matching the query across all pages.
</ResponseField>

<ResponseField name="meta.cursor.after" type="string" required>
  The ID of the last item on the current page. Pass this as the `after` query parameter to fetch the next page.
</ResponseField>

<ResponseField name="meta.cursor.before" type="string" required>
  The ID of the first item on the current page. Pass this as the `before` query parameter to fetch the previous page.
</ResponseField>

## Iterating All Pages

The following example fetches every payment in your account by looping until `has_more` is `false`:

```javascript Node.js
const BASE_URL = "https://api.moneydev.com.br/v1";
const API_KEY  = "sk_live_yourkey";

async function fetchAllPayments() {
  const allPayments = [];
  let after = null;

  do {
    const url = new URL(`${BASE_URL}/payments`);
    url.searchParams.set("limit", "100");
    if (after) {
      url.searchParams.set("after", after);
    }

    const response = await fetch(url.toString(), {
      headers: {
        "Authorization": `Bearer ${API_KEY}`,
        "Content-Type": "application/json",
      },
    });

    if (!response.ok) {
      throw new Error(`API error: ${response.status}`);
    }

    const { data, meta } = await response.json();
    allPayments.push(...data);

    after = meta.has_more ? meta.cursor.after : null;
  } while (after !== null);

  return allPayments;
}

const payments = await fetchAllPayments();
console.log(`Retrieved ${payments.length} payments.`);
```

<Tip>
  Set `limit=100` when you need to bulk-export or process large data sets. Fewer round-trips means lower latency and less risk of hitting rate limits. See the [rate limits section](/api-reference/overview#rate-limits) for per-minute request quotas.
</Tip>
