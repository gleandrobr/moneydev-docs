Every list endpoint (`GET /v1/customers`, `GET /v1/products`, `GET /v1/products/:id/offers`, `GET /v1/checkouts`) returns the same envelope and pages the same way.

## List object

```json
{
  "object": "list",
  "data": [
    { "id": "cus_2f...", "object": "customer", "...": "..." },
    { "id": "cus_1a...", "object": "customer", "...": "..." }
  ],
  "has_more": true,
  "next_cursor": "cus_1a2b3c4d-5e6f-4a7b-8c9d-0e1f2a3b4c5d"
}
```

<ResponseField name="object" type="string">
  Always `"list"`.
</ResponseField>

<ResponseField name="data" type="array">
  The page of results, newest first (by creation time).
</ResponseField>

<ResponseField name="has_more" type="boolean">
  `true` when at least one more record exists after this page.
</ResponseField>

<ResponseField name="next_cursor" type="string | null">
  The ID to pass as `starting_after` for the next page. `null` when `has_more` is `false`.
</ResponseField>

## Query parameters

<ParamField query="limit" type="integer" default="20">
  How many records to return, `1`–`100`.
</ParamField>

<ParamField query="starting_after" type="string">
  A resource ID from a previous page (typically `next_cursor`). The response starts with the record immediately after it. An ID that is malformed or does not belong to your account returns `400` with `code: "invalid_cursor"`.
</ParamField>

## Paging through every record

```javascript
async function* allCustomers(token) {
  let cursor;
  do {
    const url = new URL("https://api.moneydev.com.br/v1/customers");
    url.searchParams.set("limit", "100");
    if (cursor) url.searchParams.set("starting_after", cursor);

    const res = await fetch(url, {
      headers: { Authorization: `Bearer ${token}` },
    });
    const page = await res.json();

    yield* page.data;
    cursor = page.next_cursor;
  } while (cursor);
}
```
