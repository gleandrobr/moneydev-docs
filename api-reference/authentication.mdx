Every request to the MoneyDev API must be authenticated with an API key. Keys are issued per account and scoped to either the test environment or the live environment. You pass your key as a Bearer token in the `Authorization` header on every request.

<Warning>
  Never expose your API keys in client-side code, public repositories, or logs. Treat them with the same care as passwords. If a key is compromised, revoke it immediately from the Dashboard and issue a new one.
</Warning>

## Sending Your API Key

Include the key in the `Authorization` header using the `Bearer` scheme:

```http
Authorization: Bearer sk_live_yourkey
```

The API key is the only credential required — no session cookies or additional tokens are needed.

## Test Keys vs. Live Keys

| Prefix | Environment | Effect |
|---|---|---|
| `sk_test_` | Test | Processes simulated transactions; no real money moves. |
| `sk_live_` | Live | Processes real transactions against the Brazilian payments network. |

Use `sk_test_` keys during development and in CI pipelines. Switch to `sk_live_` keys only in your production environment.

## Code Examples

<CodeGroup>

```bash cURL
curl https://api.moneydev.com.br/v1/payments \
  -H "Authorization: Bearer sk_live_yourkey" \
  -H "Content-Type: application/json"
```

```javascript Node.js
const response = await fetch("https://api.moneydev.com.br/v1/payments", {
  method: "GET",
  headers: {
    "Authorization": "Bearer sk_live_yourkey",
    "Content-Type": "application/json",
  },
});

const data = await response.json();
console.log(data);
```

```python Python
import requests

response = requests.get(
    "https://api.moneydev.com.br/v1/payments",
    headers={
        "Authorization": "Bearer sk_live_yourkey",
        "Content-Type": "application/json",
    },
)

data = response.json()
print(data)
```

</CodeGroup>

## Authentication Errors

If your key is missing, malformed, or revoked, the API returns a `401 Unauthorized` response:

```json
{
  "error": {
    "code": "unauthorized",
    "message": "Invalid API key provided."
  }
}
```

Check the following when you receive a `401`:

1. The `Authorization` header is present and formatted as `Bearer <key>` with a single space.
2. The key has not been revoked in the Dashboard.
3. You are using the correct key for the environment you are targeting (`sk_test_` for test, `sk_live_` for live).

## Key Rotation

Rotate your API keys periodically, and always rotate immediately after a suspected exposure:

1. **Generate a new key** — go to **Dashboard → Developers → API Keys** and click **Create key**.
2. **Update your integration** — replace the old key in your environment variables or secrets manager with the new key and deploy your application.
3. **Verify traffic** — confirm that requests are succeeding with the new key.
4. **Revoke the old key** — in the Dashboard, click **Revoke** next to the old key. Revocation is immediate and irreversible.

Key rotation causes zero downtime as long as you update your integration before revoking the old key.
