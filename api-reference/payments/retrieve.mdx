Use this endpoint to fetch the full details of a single payment, including its current status, method-specific data (PIX QR code, boleto barcode, card info), fees, net amount, and any splits or metadata you attached at creation. This is useful for confirming the outcome of a payment or rendering a receipt.

## Endpoint

```
GET https://api.moneydev.com.br/v1/payments/:id
```

## Request

### Headers

| Header | Value |
|---|---|
| `Authorization` | `Bearer YOUR_API_KEY` |

### Path Parameters

<ParamField path="id" type="string" required>
  The unique identifier of the payment to retrieve. Payment IDs begin with the prefix `pay_` (e.g., `pay_01HXYZ123456ABCDEF`).
</ParamField>

## Code Example

```bash cURL
curl --request GET \
  --url https://api.moneydev.com.br/v1/payments/pay_01HXYZ123456ABCDEF \
  --header 'Authorization: Bearer YOUR_API_KEY'
```

## Response

### Response Fields

<ResponseField name="id" type="string">
  Unique payment identifier with the prefix `pay_`.
</ResponseField>

<ResponseField name="status" type="string">
  Current payment status. Possible values:
  - `pending` — awaiting customer action or bank confirmation
  - `authorized` — card authorized but not yet captured
  - `paid` — payment confirmed and funds received
  - `failed` — payment attempt was unsuccessful
  - `refunded` — payment has been fully refunded
  - `partially_refunded` — payment has been partially refunded
  - `expired` — PIX or boleto expired before payment
  - `cancelled` — payment was cancelled before capture
</ResponseField>

<ResponseField name="method" type="string">
  The payment method: `pix`, `boleto`, `credit_card`, or `debit_card`.
</ResponseField>

<ResponseField name="amount" type="integer">
  The original charged amount in centavos.
</ResponseField>

<ResponseField name="currency" type="string">
  Always `"BRL"`.
</ResponseField>

<ResponseField name="net_amount" type="integer">
  The amount in centavos that will be settled to your account after MoneyDev fees are deducted. Only populated once the payment reaches `paid` status.
</ResponseField>

<ResponseField name="fee" type="integer">
  The MoneyDev processing fee for this payment in centavos. Only populated once the payment reaches `paid` status.
</ResponseField>

<ResponseField name="description" type="string">
  The payment description provided at creation, if any.
</ResponseField>

<ResponseField name="customer" type="object">
  The customer associated with this payment.

  <Expandable title="customer fields">
    <ResponseField name="customer.id" type="string">
      The customer's MoneyDev ID (`cus_...`).
    </ResponseField>
    <ResponseField name="customer.name" type="string">
      Full name of the customer.
    </ResponseField>
    <ResponseField name="customer.email" type="string">
      Customer's email address.
    </ResponseField>
    <ResponseField name="customer.cpf" type="string">
      Individual tax ID (CPF), if stored.
    </ResponseField>
    <ResponseField name="customer.cnpj" type="string">
      Company tax ID (CNPJ), if stored.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the payment was created.
</ResponseField>

<ResponseField name="paid_at" type="string">
  ISO 8601 timestamp of when the payment was confirmed. `null` if not yet paid.
</ResponseField>

<ResponseField name="expires_at" type="string">
  ISO 8601 timestamp of when the payment will expire. Relevant for `pix` and `boleto` methods. `null` for card payments.
</ResponseField>

<ResponseField name="pix" type="object">
  Present when `method` is `"pix"`. Contains PIX-specific fields.

  <Expandable title="pix fields">
    <ResponseField name="pix.qr_code" type="string">
      The EMV payload string used to generate the QR code image.
    </ResponseField>
    <ResponseField name="pix.qr_code_url" type="string">
      A hosted URL serving a ready-to-display QR code PNG image.
    </ResponseField>
    <ResponseField name="pix.expires_at" type="string">
      ISO 8601 timestamp when the PIX QR code expires.
    </ResponseField>
    <ResponseField name="pix.end_to_end_id" type="string">
      The Banco Central end-to-end identifier (`E...`). Populated after payment is confirmed.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="boleto" type="object">
  Present when `method` is `"boleto"`. Contains boleto-specific fields.

  <Expandable title="boleto fields">
    <ResponseField name="boleto.barcode" type="string">
      The numeric barcode line for the boleto.
    </ResponseField>
    <ResponseField name="boleto.url" type="string">
      A hosted URL to view or download the printable boleto PDF.
    </ResponseField>
    <ResponseField name="boleto.due_date" type="string">
      The boleto expiry date in `YYYY-MM-DD` format.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="card" type="object">
  Present when `method` is `"credit_card"` or `"debit_card"`. Contains card-specific fields.

  <Expandable title="card fields">
    <ResponseField name="card.last4" type="string">
      Last four digits of the card number.
    </ResponseField>
    <ResponseField name="card.brand" type="string">
      Card brand: `visa`, `mastercard`, `elo`, `amex`, `hipercard`.
    </ResponseField>
    <ResponseField name="card.installments" type="integer">
      Number of installments for credit card payments.
    </ResponseField>
    <ResponseField name="card.authorization_code" type="string">
      Authorization code returned by the issuing bank.
    </ResponseField>
    <ResponseField name="card.nsu" type="string">
      Network Sequence Unit (NSU) from the acquirer.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="splits" type="array">
  An array of split recipients, if this payment was created with splits. Each item contains `recipient_id`, `amount`, and `status`.
</ResponseField>

<ResponseField name="metadata" type="object">
  The key-value metadata object attached at creation. Returns an empty object `{}` if none was provided.
</ResponseField>

<Note>
  **Prefer webhooks over polling in production.** Repeatedly calling this endpoint to detect a status change (e.g., waiting for `pending` → `paid`) adds unnecessary latency and can consume your rate-limit quota. Instead, configure a webhook listener for the `payment.paid`, `payment.failed`, and `payment.expired` events in your [MoneyDev Dashboard](https://dashboard.moneydev.com.br) — MoneyDev will push a real-time notification to your endpoint the moment a payment status changes.
</Note>
