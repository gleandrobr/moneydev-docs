The MoneyDev API is a REST API for building payment flows: register customers, model what you sell as products and offers, and open hosted checkout sessions your buyers pay through. It speaks JSON over HTTPS and authenticates with OAuth 2.0 access tokens.

## Base URL

```text
https://api.moneydev.com.br
```

Authentication and service endpoints live at the root; every business resource lives under the `/v1` prefix.

| Path | Purpose |
|---|---|
| `POST /oauth/token` | Exchange client credentials for an access token |
| `GET /.well-known/oauth-authorization-server` | OAuth authorization server metadata |
| `GET /.well-known/jwks.json` | Public keys used to sign access tokens |
| `GET /health` | Service health probe (no auth) |
| `/v1/*` | Customers, products, offers, and checkouts |

## Versioning

The current version is **v1**, carried in the URL path. Additive changes — new endpoints, new response fields — ship within `v1` without notice, so parse responses tolerantly. A breaking change would ship under a new prefix.

## Requests

Send a JSON body with `Content-Type: application/json` on `POST` and `PATCH` requests. The one exception is `POST /oauth/token`, which takes `application/x-www-form-urlencoded` (see [Authentication](/api-reference/authentication)).

Unknown body fields are rejected with a `400` rather than ignored.

## Responses

Every response is JSON.

- **Success** — a `2xx` status and the resource object. Creation endpoints return `201`; reads and updates return `200`.
- **Error** — a `4xx` or `5xx` status and a structured [error object](/api-reference/errors).

Single resources carry an `object` field naming their type (`"customer"`, `"product"`, `"offer"`, `"checkout"`). Collection endpoints return a [list object](/api-reference/pagination).

## Resource IDs

IDs are strings with a type prefix and a UUID. The prefix tells you what kind of object an ID points at:

| Prefix | Object |
|---|---|
| `cus_` | Customer |
| `prod_` | Product |
| `offer_` | Offer |
| `checkout_` | Checkout session |
| `item_` | Checkout line item |
| `seller_` | Seller (your account) |
| `client_` | API client |

Example: `cus_9b2c4f1a-3d5e-4a7b-8c9d-1e2f3a4b5c6d`.

## Money

Amounts are integers in the currency's **minor unit** (centavos for BRL). `R$ 49,90` is `4990`. Currency codes are uppercase ISO 4217 — MoneyDev settles in `BRL`.

## Request IDs

Every response includes an `X-Request-Id` header, and error bodies repeat it as `error.request_id`. Include it when contacting [support](mailto:support@moneydev.com.br).

## A typical integration

<Steps>
  <Step title="Get an access token">
    Exchange your client credentials at `POST /oauth/token`. See [Authentication](/api-reference/authentication).
  </Step>
  <Step title="Create a product and its offer">
    A [product](/api-reference/products/create) is what you sell; an [offer](/api-reference/offers/create) is a specific price for it.
  </Step>
  <Step title="Open a checkout">
    [Create a checkout](/api-reference/checkouts/create) for an offer. The response includes a `checkout_url`.
  </Step>
  <Step title="Send the buyer to the checkout">
    Redirect them to `checkout_url`, the hosted page where they pay with Pix. Poll [the checkout](/api-reference/checkouts/retrieve) until `status` is `completed`.
  </Step>
</Steps>
