<Info>
  `GET /v1/checkouts/{checkoutId}` &nbsp;·&nbsp; Requer o escopo `checkouts:read`
</Info>

Busca uma sessão de checkout. Consulte este endpoint periodicamente depois de enviar o comprador para a `checkout_url` para ver quando o `status` vira `completed`. Se a sessão estiver `open` e já tiver passado do `expires_at`, esta chamada a marca como `expired` antes de retornar.

## Parâmetros de caminho

<ParamField path="checkoutId" type="string" required>
  O ID do checkout, ex. `checkout_7f8a9b0c-1d2e-4f3a-8b4c-5d6e7f8a9b0c`. Se não for um ID `checkout_` válido → `400` (`invalid_checkout_id`).
</ParamField>

## Requisição

```bash cURL
curl https://api.moneydev.com.br/v1/checkouts/checkout_7f8a9b0c-1d2e-4f3a-8b4c-5d6e7f8a9b0c \
  --header "Authorization: Bearer $ACCESS_TOKEN"
```

## Resposta

`200 OK` com o [objeto de checkout](/api-reference/checkouts/create#objeto-de-checkout).

| `status` | Significado |
|---|---|
| `open` | Aguardando pagamento |
| `completed` | Pago — `completed_at` está preenchido |
| `expired` | Chegou ao `expires_at` sem pagamento |
| `canceled` | Cancelado antes do pagamento |

## Erros

| Status | `code` | Causa |
|---|---|---|
| `400` | `invalid_checkout_id` | O trecho do caminho não é um ID `checkout_` válido |
| `404` | `checkout_not_found` | Não existe esse checkout na sua conta |

<Note>
  Um webhook para o seller no evento `completed` está no roadmap. Por enquanto, consulte este endpoint periodicamente.
</Note>
