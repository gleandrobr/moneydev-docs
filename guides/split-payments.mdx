If you run a marketplace, multi-vendor store, or any platform where revenue needs to be shared, MoneyDev's split payments let you distribute funds to multiple recipients in a single transaction. You define the split at payment creation time, and MoneyDev handles the settlement automatically — no manual transfers required.

## How Split Payments Work

When you create a payment, you include a `splits` array that lists each recipient and their share of the total amount. Shares can be expressed as a **fixed amount** (in centavos) or as a **percentage** of the transaction. After the payment clears, MoneyDev settles each recipient's portion directly into their registered bank account.

```
Customer pays R$100,00
      ↓
MoneyDev API
      ↓
 ┌────────────┬────────────┐
 │ Vendor A   │ Platform   │
 │ R$70,00    │ R$30,00    │
 └────────────┴────────────┘
```

---

<Steps>

### Register Recipients

Before you can split a payment, each party that will receive funds must be registered as a recipient. Recipients must provide their name, tax document, and bank account details.

```bash
POST https://api.moneydev.com.br/v1/recipients
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json
```

```json
{
  "name": "Loja do João",
  "document": "12.345.678/0001-90",
  "bank_account": {
    "bank": "341",
    "agency": "0001",
    "account": "12345-6",
    "type": "checking"
  }
}
```

**Response:**

```json
{
  "id": "rec_123",
  "name": "Loja do João",
  "document": "12.345.678/0001-90",
  "status": "pending_kyc",
  "created_at": "2024-01-15T10:00:00Z"
}
```

Repeat this step for every recipient on your platform. Note the `id` returned for each (e.g. `rec_123`, `rec_456`) — you will reference these when creating payments.

<Warning>
  **KYC is required for all recipients.** Recipients with `status: pending_kyc` cannot receive funds. Each recipient must complete identity verification through the MoneyDev dashboard before they can be included in a split. Direct your vendors or partners to complete this step before you go live.
</Warning>

### Create a Payment with Splits

Include the `splits` array in your payment request. Each entry maps a `recipient_id` to either a fixed `amount` (centavos) or a `percentage`.

```bash
curl -X POST https://api.moneydev.com.br/v1/payments \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "method": "credit_card",
    "amount": 10000,
    "currency": "BRL",
    "card_token": "tok_live_abc...",
    "customer": {
      "name": "Maria Silva",
      "email": "maria.silva@email.com",
      "tax_id": "123.456.789-09"
    },
    "splits": [
      {"recipient_id": "rec_123", "amount": 7000},
      {"recipient_id": "rec_456", "amount": 3000}
    ]
  }'
```

**Response:**

```json
{
  "id": "pay_split001",
  "status": "confirmed",
  "amount": 10000,
  "currency": "BRL",
  "method": "credit_card",
  "splits": [
    {"recipient_id": "rec_123", "amount": 7000, "status": "pending"},
    {"recipient_id": "rec_456", "amount": 3000, "status": "pending"}
  ],
  "created_at": "2024-01-20T11:00:00Z"
}
```

<Note>
  **Split amounts must equal the total payment amount.** The sum of all `amount` values (or the equivalent when using percentages) in the `splits` array must exactly equal the top-level `amount` field. If they do not match, the API returns a `400 Bad Request` error.
</Note>

### MoneyDev Settles Each Recipient Automatically

After the payment is confirmed, MoneyDev disburses each recipient's share on your normal settlement schedule. You do not need to initiate any additional transfers. You can monitor the status of each split by fetching the payment:

```bash
GET https://api.moneydev.com.br/v1/payments/pay_split001
Authorization: Bearer YOUR_API_KEY
```

Individual split statuses:

| Status | Meaning |
|---|---|
| `pending` | Awaiting settlement |
| `settled` | Funds transferred to the recipient's bank account |
| `failed` | Settlement failed (check `failure_reason`) |

</Steps>

## Fixed Amount vs. Percentage Splits

Both split types are supported and can be mixed within the same payment.

<Tabs>
  <Tab title="Fixed Amount">
    Use `amount` (in centavos) when you want each recipient to receive an exact value.

    ```json
    {
      "method": "pix",
      "amount": 10000,
      "currency": "BRL",
      "customer_id": "cus_abc123",
      "splits": [
        {"recipient_id": "rec_123", "amount": 7000},
        {"recipient_id": "rec_456", "amount": 3000}
      ]
    }
    ```

    The vendor receives exactly R$70,00 and the platform receives exactly R$30,00.
  </Tab>
  <Tab title="Percentage">
    Use `percentage` when each recipient's share should scale with the transaction value.

    ```json
    {
      "method": "pix",
      "amount": 10000,
      "currency": "BRL",
      "customer_id": "cus_abc123",
      "splits": [
        {"recipient_id": "rec_123", "percentage": 70.0},
        {"recipient_id": "rec_456", "percentage": 30.0}
      ]
    }
    ```

    Percentages must sum to exactly `100.0`. MoneyDev rounds to the nearest centavo if needed and adjusts the last recipient's portion to cover any rounding difference.
  </Tab>
</Tabs>

## Charging a Platform Fee

You can retain a portion of every transaction as a platform fee by including your own recipient ID in the `splits` array. This keeps the accounting transparent and avoids a separate transfer step.

```json
{
  "splits": [
    {"recipient_id": "rec_vendor", "percentage": 90.0},
    {"recipient_id": "rec_platform", "percentage": 10.0}
  ]
}
```

In this example, the platform keeps 10% of every sale processed through it.
