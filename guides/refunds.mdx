Whether a customer changes their mind or an error occurred at checkout, MoneyDev lets you issue full or partial refunds directly through the API. Refund behaviour varies by payment method — this guide covers eligibility rules, the step-by-step process, and what to expect on the customer's end.

---

## Refund Eligibility by Payment Method

| Method | Refund Type | Window |
|---|---|---|
| **PIX** | Full or partial | Up to 90 days after payment |
| **Credit card** | Full or partial | Up to 180 days after payment |
| **Boleto** | Via PIX devolution only | Requires customer's PIX key |
| **Debit card** | Full only | Up to 180 days after payment |

<Warning>
  **Boleto refunds require an extra step.** Because boleto is a cash-equivalent instrument, MoneyDev cannot reverse the payment to the original barcode. Instead, refunds are processed as a PIX devolution. You must collect the customer's PIX key (CPF, phone, email, or random key) before initiating the refund. See Step 2 below for details.
</Warning>

<Steps>

### Find the Payment ID

Every refund is tied to a specific payment. Retrieve the `payment_id` from your database or by querying the API.

```bash
GET https://api.moneydev.com.br/v1/payments/pay_xyz456
Authorization: Bearer YOUR_API_KEY
```

```json
{
  "id": "pay_xyz456",
  "status": "confirmed",
  "amount": 10000,
  "currency": "BRL",
  "method": "pix",
  "customer_id": "cus_abc123",
  "created_at": "2024-01-15T10:07:30Z"
}
```

Confirm that the payment `status` is `confirmed` and that you are within the eligible refund window for the payment method before proceeding.

### Issue the Refund

Send a `POST` request to `/payments/{id}/refund` with the amount you want to refund (in centavos) and a reason code.

```bash
curl -X POST https://api.moneydev.com.br/v1/payments/pay_xyz456/refund \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 5000,
    "reason": "customer_request"
  }'
```

For **boleto refunds**, include the customer's PIX key in the request body:

```bash
curl -X POST https://api.moneydev.com.br/v1/payments/pay_xyz456/refund \
  -H "Authorization: Bearer YOUR_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "amount": 10000,
    "reason": "customer_request",
    "pix_key": "maria.silva@email.com"
  }'
```

Accepted `reason` values: `customer_request`, `duplicate`, `fraud`, `product_not_received`, `other`.

### Check the Refund Status

A successful request returns a refund object:

```json
{
  "id": "ref_def789",
  "payment_id": "pay_xyz456",
  "amount": 5000,
  "reason": "customer_request",
  "status": "pending",
  "created_at": "2024-01-20T14:30:00Z"
}
```

The `status` will be one of:

- `pending` — the refund has been submitted and is being processed.
- `succeeded` — the funds have been returned to the customer.
- `failed` — the refund could not be processed (check the `failure_reason` field).

### Handle the `payment.refunded` Webhook

When the refund settles, MoneyDev fires a `payment.refunded` event to your webhook endpoint. Update your order state accordingly.

```json
{
  "event": "payment.refunded",
  "created_at": "2024-01-20T14:31:05Z",
  "data": {
    "id": "ref_def789",
    "payment_id": "pay_xyz456",
    "amount": 5000,
    "reason": "customer_request",
    "status": "succeeded",
    "created_at": "2024-01-20T14:30:00Z"
  }
}
```

```javascript
app.post("/webhooks/moneydev", express.json(), async (req, res) => {
  const { event, data } = req.body;

  if (event === "payment.refunded") {
    await db.orders.update(
      { payment_id: data.payment_id },
      { status: "refunded", refund_id: data.id }
    );
    await notifyCustomer(data.payment_id, data.amount);
  }

  res.sendStatus(200);
});
```

</Steps>

## Refund Object Fields

<ResponseField name="id" type="string">
  Unique identifier for the refund (e.g. `ref_def789`).
</ResponseField>

<ResponseField name="payment_id" type="string">
  The ID of the original payment that was refunded.
</ResponseField>

<ResponseField name="amount" type="integer">
  Amount refunded, in centavos (BRL). For a partial refund this will be less than the original payment amount.
</ResponseField>

<ResponseField name="reason" type="string">
  The reason code provided when the refund was created.
</ResponseField>

<ResponseField name="status" type="string">
  Current status of the refund: `pending`, `succeeded`, or `failed`.
</ResponseField>

<ResponseField name="created_at" type="string">
  ISO 8601 timestamp of when the refund was created.
</ResponseField>

## Full vs. Partial Refund Examples

<Tabs>
  <Tab title="Full Refund">
    To refund the entire payment amount, set `amount` equal to the original payment value.

    ```bash
    curl -X POST https://api.moneydev.com.br/v1/payments/pay_xyz456/refund \
      -H "Authorization: Bearer YOUR_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "amount": 10000,
        "reason": "customer_request"
      }'
    ```

    **Response:**

    ```json
    {
      "id": "ref_full001",
      "payment_id": "pay_xyz456",
      "amount": 10000,
      "reason": "customer_request",
      "status": "pending",
      "created_at": "2024-01-20T14:30:00Z"
    }
    ```
  </Tab>
  <Tab title="Partial Refund">
    To refund only part of the payment, set `amount` to the portion you want to return. You can issue multiple partial refunds as long as the cumulative total does not exceed the original payment amount.

    ```bash
    curl -X POST https://api.moneydev.com.br/v1/payments/pay_xyz456/refund \
      -H "Authorization: Bearer YOUR_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "amount": 3000,
        "reason": "product_not_received"
      }'
    ```

    **Response:**

    ```json
    {
      "id": "ref_part001",
      "payment_id": "pay_xyz456",
      "amount": 3000,
      "reason": "product_not_received",
      "status": "pending",
      "created_at": "2024-01-20T15:00:00Z"
    }
    ```
  </Tab>
</Tabs>

## Refund Timeline

| Method | When the Customer Sees the Funds |
|---|---|
| **PIX** | Usually within minutes; up to 1 business day at most |
| **Credit card** | 5–10 business days for it to appear on the card statement (depending on the issuing bank and billing cycle) |
| **Boleto (PIX devolution)** | Usually within minutes after the PIX key is confirmed |
| **Debit card** | 5–10 business days |
