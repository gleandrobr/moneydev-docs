MoneyDev authenticates API requests with **OAuth 2.0 client credentials**. Your server exchanges a client ID and secret for a short-lived access token, then sends that token on every `/v1` call.

<Warning>
  Your client secret has full access to your account. Keep it server-side, in an environment variable. Rotate it from the [Dashboard](https://dashboard.moneydev.com.br) if it leaks.
</Warning>

## 1. Get your credentials

In the [Dashboard](https://dashboard.moneydev.com.br) → **API Keys**, create an API client. You get a `client_id` and a `client_secret` (shown once). Each client is granted a set of scopes such as `customers:write` or `checkouts:write`.

## 2. Get an access token

```bash
curl --request POST https://api.moneydev.com.br/oauth/token \
  --user "$MONEYDEV_CLIENT_ID:$MONEYDEV_CLIENT_SECRET" \
  --header "Content-Type: application/x-www-form-urlencoded" \
  --data grant_type=client_credentials
```

```json
{
  "access_token": "eyJhbGciOiJSUzI1NiIsInR5cCI6ImF0K2p3dC...",
  "token_type": "Bearer",
  "expires_in": 900,
  "scope": "customers:write checkouts:write"
}
```

The token is valid for 15 minutes. Cache it, reuse it, and request a new one shortly before it expires — there is no refresh token.

## 3. Call the API

```bash
curl https://api.moneydev.com.br/v1/me \
  --header "Authorization: Bearer $ACCESS_TOKEN"
```

A missing or expired token returns `401`; a token without the scope an endpoint needs returns `403`.

<Note>
  Full details — Basic-auth encoding, scopes, token-endpoint errors, and the `/.well-known` discovery endpoints — are in the [API reference](/api-reference/authentication).
</Note>
